# 比赛几何检查：整车外廓与UID覆盖

本功能把路线/凸轮的数学验证与比赛几何检查分开；不模拟RFID电磁场、固件、灯光和语音，不计算官方总成绩。整车外廓、UID全覆盖和重复访问诊断已实现并在R2025b验证，记录见[CHG-013](changes/2026/2026-10-31-013-contest-geometry.md)。

## 两种车身区域必须分开

**外廓区域**应包含车辆在运行中的全部水平投影，包括轮子、车壳和线缆；若用矩形包络，是保守的占地模型。整个矩形必须在场地边界以内，碰线也不是通过。有转向轮时，要把其最大转动外廓纳入包络。

**覆盖区域**必须完全位于车身实际连续遮挡的投影内部。它可以选底部一个连续矩形，但不能直接拿整个外接包围盒当作遮挡区域，否则车身缺口/圆角外侧的标签可能被误判为完全遮挡。用内接矩形可能保守地漏掉真实覆盖，但不应凭空增加覆盖范围。

所有尺寸相对前轮转向轴，局部X右、Y前；外廓和覆盖区域的尺寸确认与现场标签直径确认必须区分。教学默认值、比赛最大外形尺寸和本队实际尺寸不能混用；未确认时只能进行假设诊断。

## 几何依据

使用车体航向ψ而不是前轮转角或路线切线。世界前向为(cosψ,sinψ)，右向为(sinψ,-cosψ)；车体点(x,y)的世界位置为前轮轴位置＋x×右向＋y×前向。

对轴对齐场地，将车体矩形四角变换到世界坐标后，逐角检查到四条边界的有符号距离。最小距离为边界余量；再减去用户设定安全余量，必须严格大于零。该结论在各检查姿态成立，不自动证明采样间连续轨迹。

对圆形UID标签，将标签圆心变换到车体局部坐标。全覆盖等价于圆心在覆盖矩形中，且到每条边的距离不小于标签半径。最小距离减去半径就是覆盖余量。标签直径不是RFID读卡直径。

相邻采样连续覆盖视为同一次访问，离开后再进入计另一次；同位置的起终点仍需要两次访问。乱序、重复、同时发生的歧义和覆盖不足应分别报告。采样检测可能漏掉很短事件，增加密度有帮助但不构成连续保证；完整比赛仍需实际读卡、固件和裁判判定。

## 实施边界

本次增加独立诊断，不自动修改传动比、路线、车体尺寸或优化权重。现有数值合格不能盖过比赛几何未知/失败；几何候选导出仍不是制造批准。发车引入段、停车段未纳入的项目必须保留其范围限制。

## 本队设计配置

用户在2026-10-31提供《新能源2027小车计算表格 (1).xlsx》并确认“顶球/生物质能”标题是旧模板。确认采用：轴距110 mm、主动轮X=60 mm、从动轮X=-105 mm、传感器(20,0) mm、主动轮直径135 mm、转向偏距20 mm、零位基准直径150 mm；传动比仍为35。新入口`camdesign.teamSolarProject()`，普通`launch_cam_app`默认使用它；历史`solarTestProject()`不改，已有MAT不自动替换。

确认的是设计值，不是制造实测。原表没有完整外包络和连续遮挡区域；A12“打卡点到车尾距离150”也不能无条件转换为前轮轴到车尾的距离。参数出处与未采用字段见[data/team_solar_design_20261031.json](../data/team_solar_design_20261031.json)。

表中C12用5×7得到35，后续两组齿数150/30和120/30相乘则为20，故不据齿数覆盖用户确认的35。用户随后明确纠正：E3=12238 mm来自原版仿真后填入，不能因与规则有效距离数值相同就推定来源。B19引用E3，用户进一步说明用于凸轮利用率，即工作段占整圈；原版具体字段及同输入仍未核验。按表中135 mm、35计算，利用率82.4439%、工作角296.7982°、余角63.2018°。保留为原版工作段参考结果，暂不据此替换软件主动轮行程或宣称同输入对照完成。凸轮厚度3 mm未在本轮明确确认的参数列表内，仍保留旧记录值，且不参与二维轮廓计算；启动航向/初始转角、外廓、实际读卡范围仍须独立核对。


## 初始设计状态与优化质量分开

本队新参数种子已能计算，初始最大压力角约80.26°、实际回程约58.10°，尚未满足原阈值。这里只检查配置能否运行，未做优化质量试验；不能凭这个未经优化的种子判断优化器能力，更不能声称本队凸轮已合格。

## API与采样边界

- `camdesign.contestGeometrySettings(params)`只读可选`params.contestGeometry`，旧项目缺省返回未配置，不自动写入项目。
- `camdesign.contestGeometry(route,targets,bounds,params)`检查给定姿态序列，要求`route.front`与车体`route.heading`。它不需要凸轮成功生成。
- `camdesign.verifyContestGeometry(project)`重新计算路线并加密，默认4倍、最少1001点，必要时继续加密至最多20001；检查目标是最大前轮采样步长5 mm、航向步长0.5°。粗细两档事件序列一致也不能证明不存在短暂漏检。
- 设置包含外廓left/right/front/rear、覆盖区域X/Y有符号上下界、UID直径、场界及覆盖余量。旧项目缺配置返回未配置；填齐但未确认尺寸/场界/标签或连续遮挡区域时仅诊断。
- 触边和全覆盖恰好相切均按`1e-9 mm`数值保护保守拒绝；后者是本版保守判定，不宣称规则另有正余量要求。
- `competitionCertified`、`rfidCertified`、`continuousCertified`始终为false。可以通过的是指定输入下的采样几何检查。

复核必须实际增加采样点数。达到采样上限时，不允许把同一网格算两遍称为“两档采样通过”；即使步长已满足，也应说明缺少独立加密验证。

## 界面操作

1. 在左侧常驻按钮点“比赛几何”，会同时打开参数页和下方结果页。
2. 输入外包络左/右/前/后距离、连续遮挡区域的X/Y上下界、UID直径和两类余量。未知值留空；已知的零余量填0。
3. 未现场核实也能做假设诊断；只有确实核实尺寸、场界、标签，以及连续遮挡内接区域后才能勾选对应确认框。勾选本身不等于实测证据。
4. 点击“独立检查当前路线”。即使凸轮生成失败，只要路线运动学可计算，也可以检查路线。固定凸轮反推模式下先退出反推；本入口不将设计路线冒充反推结果。
5. 结果表列出边界最差余量、各次访问覆盖余量、访问顺序和采样分辨率。“定位最差外廓”放大到最差姿态；选择标签行或点“定位所选标签”查看覆盖内接矩形和该次访问。
6. 修改路线、尺寸或确认状态后，旧诊断清除。完整模型切换备份包含已应用和待应用的比赛几何输入；旧备份无该扩展时恢复后须重查。

导出候选时重新运行独立检查并写入`report.json`的`contestGeometry`，仍保留`candidate_geometry_not_manufacturing_release`状态。新检查目前不进入六项优化分，也不自动挪路线；它用于发现和定位问题，指导后续调形及实车核验。
