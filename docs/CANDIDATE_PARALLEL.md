# 候选并行搜索

本项在CHG-020加入，默认关闭。它与“后台计算”是两个独立设置：后台让界面与计算同时运行，候选并行让多个CPU线程同时计算同一轮的不同探针。

新开窗口的“候选并行”菜单可以开关并选择2或4个候选worker。旧窗口须在空闲、完整保全之后显式执行 `cam_candidate_ui(app,'install')`，本次执行器未迁移用户窗口。选择后台计算，再选可行性四方向或接力/多起点。其他搜索方法不支持此开关时明确拒绝，不悄悄改回串行。

首次可通过“准备候选进程池”创建一个协调进程，NumThreads配额为选择的worker数。已有足够配额的进程池可复用。已有不兼容池不会自动删除；准备菜单只在所有future空闲且用户确认后替换。初始化会等待。前台兼容与候选并行同时开启时拒绝启动，须明确选择后台或关闭候选并行。

协调进程独占PhysicalEvaluationBudget。线程只收到普通项目数据和fullCheck标志，不接收账本。±X/±Y探针全部从冻结best生成，以原顺序排列，提交前预留，最多同时运行N个，结果按原索引归并。排序、接受、完整几何复核、加密网格、硬件、权重及阈值规则不变。接力仍逐阶段及逐起点执行，只并行四方向探针。

只有确实返回的物理尝试计入Used；失败也计入Invalid。未能判断是否执行的基础设施失败保留Reserved，不释放后重试，也不冒充真实次数。正常停止在整轮探针结算后处理。候选并行中的强制取消也是先结算，再取消发布和恢复原状态；不会遗弃在飞任务。完整outcome（含candidateLedger）先存任务独占-result.mat，再处理发布/取消。

实测原型：Process协调worker配置4线程后，backgroundPool确实有4个worker，两个小任务重叠约0.509秒。实际模型探针在最终检查中重叠约0.002秒；仅证明真实并发，不证明比赛输入加速比例。手写3点输入在预算4、11、100下串并行候选及实际调用数相同，接力60次预算检查相同，失败计数、停止、UI运行、取消恢复及完整结果留存通过。没有比赛数据测速。详细证据见[CHG-020](changes/2026/2026-10-31-020-candidate-parallel.md)。
