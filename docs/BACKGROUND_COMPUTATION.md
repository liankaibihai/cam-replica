# 后台计算与界面响应

本项接入状态及实际检查以 [CHG-019](changes/2026/2026-10-31-019-background-computation.md) 为准。

## 为什么原来会卡

此前本版的计算按钮和优化按钮直接在MATLAB主执行线程运行数值代码。一轮多控制点试探之间没有UI回调时，界面会等待；优化回调还会重建三张图、图例和评分表，缺少缓存结果时额外计算一次模型。`drawnow`只能提供处理界面事件的机会，不会把这些数值任务移到其他线程。

## 本轮并发范围

主线程负责界面，一个后台任务负责完整数值过程。普通计算和支持线程的优化使用`backgroundPool`；接力/多起点包含的SQP在R2025b中不支持线程，因此运行前明确选择进程worker。用户选择的路线模型、目标顺序、传动比、评分权重、采样与验收门限保持原语义。搜索迭代仍按原顺序比较和接受候选，共享物理评价预算仍只由同一个优化任务持有。

这能让计算与界面响应并发，不代表每个优化候选都分配到多个CPU核心。本机探针得到8个后台workers，但当前单个优化任务不会据此变成8路搜索；不能据此声称8倍加速。首次后台调用可能包含初始化和编译耗时。已有线程池和后台池共享线程资源，其他MATLAB任务也可能影响调度。

后台只能接收项目副本、算法选项和消息通道，不能直接访问App或绘图对象。界面仅发布与当前任务编号相符的消息。路线、凸轮和评分预览最多每1.5秒发送一次，前一条显示确认后才允许下一条；完整历史最终返回。优先复用优化器缓存的显示结果，必要的显示/结束后处理求值在后台执行、与搜索评价次数分列。节流不改变实际迭代次数，也不降低计算网格。过程预览不是最终加密验收。

## 界面用法

顶部菜单“计算执行方式”提供后台计算、前台兼容和强制取消。“计算凸轮”“迭代优化”和“实际轮廓闭环检查”的按钮入口使用后台执行；计算时可浏览评分、详情与训练页，改变工程方案的操作保持禁用，避免结果与输入混用。

普通新启动默认安装后台入口。对存活旧窗，源码变化本身不会自动激活；空闲时再次运行`launch_cam_app`可安装菜单且保留当前项目。显式选择过的前台模式会继续保留，须从菜单选择后台。运行中的窗口不安装、不打断。

当前没有把地图映射、导出、固定凸轮试跑或手动加密查看等所有动作都改为后台。三张图的渲染仍由主线程负责，刷新时可能短暂等待。首次创建进程池也可能等待；不能把这些局限说成“全软件完全不卡”。

需要进程的算法优先复用已有进程池，没有池时创建1个worker；需要Parallel Computing Toolbox。若当前已有用户自己的Threads池，会明确提示冲突并保留该池，不自动删除或替换。用户可明确选前台兼容，或自行处理已有池。普通后台线程按本机MATLAB许可和资源运行。

## 停止与结果保全

正常停止请求由算法在可响应位置处理，允许返回按其规则保留的完整候选；单次数值调用尚未返回时，停止不一定立即完成。强制取消和异常没有完成最终验收，不能标成优化成功；有预览时恢复原确认方案。后台错误不会自动重跑，也不会静默改成前台执行。

开始前完整备份写入`local/background_jobs/<任务编号>.mat`；后台outcome返回后，在界面输入/结果保护检查之前另存`<任务编号>-result.mat`。这样输入变化或显示报错拒绝发布时，已算完的候选仍可追查。强制取消尚未返回的任务不保证拥有最终outcome。`cam_app_async('status',camReplicaApp)`可查询模式、任务状态及结果保存路径；备份和结果为本机文件，不入Git。

只清理当前App拥有的future、监听器和消息通道；不能关闭共享池或取消其他任务。关闭窗口和启动新任务时，旧任务消息必须失效。显式前台兼容模式用于排障，不能以悄悄退回阻塞计算冒充后台运行。

## 兼容性证据

独立R2025b探针确认Parallel Computing Toolbox 25.2可用；backgroundPool上两组简单任务有0.418秒重叠，取消及双向停止消息成功。三点手写合成路线的完整`evaluate`结果与同步`isequaln`相等。小型二次目标仅证明`fmincon`的interior-point路径；实际接力检查随后遇到`parallel:threadpool:DisallowedBuiltin`（`nlpSQP`不支持线程），因此不能把前一个成功泛化成所有fmincon算法可在线程运行。这些只是能力和兼容性证据；不是比赛优化速度/质量对照。

在线MathWorks页面目前展示R2026b；本项目R2025b行为由本机探针和实际生产入口检查确认。参考：[线程支持](https://www.mathworks.com/help/matlab/matlab_prog/run-functions-on-threads.html)、[后台池及限制](https://www.mathworks.com/help/matlab/ref/parallel.backgroundpool.html)、[响应式App](https://www.mathworks.com/help/matlab/matlab_prog/use-the-background-to-make-your-apps-more-responsive.html)。线程worker中的嵌套backgroundPool不构成本轮候选并行方案；不复制预算对象给多个worker分别花同一份额度。

最终`check_background_ui`在独立R2025b实例的13组检查通过，涵盖7种UI优化方法、后台/同步结果和搜索决策一致性、预览/详情浏览、正常停止、强制取消回退、旧消息拒绝、结果先存后发、关闭清理及已有池保护。计算/优化发布路径的主线程`evaluate`调用数均为0；这是被检查路径的证据，不表示所有UI操作都不计算。完整记录见[CHG-019](changes/2026/2026-10-31-019-background-computation.md)，[本地证据哈希](../data/background_computation_20261031.json)。

候选多核搜索已单独提供，默认关闭；支持可行性四方向及接力的四方向阶段，详见[候选并行搜索](CANDIDATE_PARALLEL.md)。后台计算本身不等于候选并行。
