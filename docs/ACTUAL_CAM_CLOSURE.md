# 实际轮廓驱动的反推闭环

当前新增链条为：**冻结实际XY轮廓 → 圆形推杆接触 → 推程 → 前轮转角 → 车辆运动 → 传感器路线**。原 `simulate` 继续作为理论凸轮对照；实际模式不读取 `pitch/radius/workRadius` 求运动规律。

## 使用

1. 完成路线及凸轮计算，应用或还原待处理的训练设置。
2. 顶部“反推来源”默认“实际轮廓接触”。点“固定凸轮反推”叠加实际接触驱动的传感器路线；在车体表修改轮径、传动比、接触半径、转向偏距等，再点“更新反推”。凸轮XY保持冻结，退出恢复原设计。理论模式须在退出后显式选择。
3. 底部“轮廓闭环”页点“检查当前实际轮廓”，固定同一折线进行两档相位积分，显示前轮／传感器／转角偏差、积分稳定、接触残差、穿透、打卡、访问顺序和场界。紫虚线为实际轮廓反推传感器路线。
4. 输入改变后旧闭环表失效；失败只显示拒绝原因，不生成假通过。闭环检查与优化独立，不会自动换模型、调传动比或重新优化路线。

## 接触几何

实际轮廓是封闭折线。每条线段与半径r的圆盘作几何扩张，形成两侧偏移边及两端半圆；程序求这些区域与推杆射线的最外交点。该位置代表滚子从外侧靠近凸轮时遇到的接触，不用“轮廓点极径加r”近似，也不只检查顶点圆盘。

求解后独立计算滚子中心到所有轮廓线段的最近距离，核查切触和不穿透；反向排列顶点不应改变几何结果。多处接触时记录接触状态，并对活动接触使用保守压力角。轮廓自交、非有限、未闭合、退化、原点不在内部会被拒绝。

本版支持正接触半径、径向平移推杆、正相位对应实体凸轮顺时针旋转、固定推杆在+X的约定。零接触半径或其他旋向约定明确拒绝；不能把装配旋向不匹配交给算法猜测。折线是用户实际输入的几何，积分加密不会偷偷重新生成或平滑凸轮。

车辆用无侧滑刚性运动学积分。RK4每步的首、末和中间相位都直接求实际折线接触，再从位移恢复转角，不用理论运动曲线插值驱动。

## 怎样理解检查结果

- **闭环误差**：实际轮廓驱动的路线与设计路线之差，分别报告最大值和RMS。
- **积分加密误差**：固定同一实际轮廓，只把相位步长减半，比较两次反推结果。它检查数值积分稳定，不证明原始轮廓足够密。
- **接触残差／穿透**：当前采样相位下圆盘与整个折线的几何关系；不代表接触动力学、预紧力或摩擦验证。
- **几何门禁**：压力角、回程、转角、打卡、访问及场界等仍须满足；数值闭环通过不能覆盖这些失败。

默认闭环位置门限2 mm沿用现有 `autoTuneNumericalChecks.inverseToleranceMM` 的内部数值尺度，积分加密差门限0.05 mm、接触残差1e-7 mm是此独立检查设置；报告记录容差及来源。**这些不是实车打卡容差、加工公差或官方比赛门限。** 关注实际误差数值，而不只看“通过”。

## 接口

```matlab
[q, contact] = camdesign.contactFromOutline(outlineXY, rollerRadius, phase);
simulation = camdesign.simulateActual(result.cam, project.params, ...
    result.route.front(1,:), result.route.heading(1));
[report, simulation] = camdesign.verifyActualClosure(project, result);
```

`simulateActual`使用实际XY及显式工作相位范围/序列，传动比默认采用当前传入物理参数；`GearRatio`只用于用户明确试调。只给实际轮廓而无工作相位信息时，不从顶点极角猜测工作段。报告与simulation可用MATLAB的save保存；原导出候选报告并不会自动包含尚未执行的实际闭环检查。

闭环检查目前由独立按钮／接口按需执行，未自动替换全自动优化原有验收流程。全自动训练结束不表示已经运行此项。比较用当前设计路线按主动轮相位插值得到参考，误差包含当前路线离散化影响；积分加密只检验冻结轮廓的反推稳定性，不把当前参考当连续精确真值。

## 限制和证据

实际接触模型仍不含轮胎打滑、槽杆间隙、有限刚度、摩擦、惯性、弹跳和加工误差。折线与相位有限采样不能形成连续接触全局认证。队伍实车尺寸、零位与旋向未标定；全链模型检查不是实车验证。

代码及独立测试记录见[CHG-008](changes/2026/2026-10-31-008-actual-cam-closure.md)。既有007的点云局部接触检查保留为历史，不替代本轮线段接触及完整车辆反推。
